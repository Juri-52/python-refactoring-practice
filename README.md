# 第11回 自主課題：図書館の延滞料金プログラムをリファクタリングしよう

学校の図書館では、返却が遅れた本の延滞料金を計算します。配布されたプログラムは、3件の貸出について料金を計算し、利用明細を表示します。

現在の計算結果は正しいものの、分かりにくい変数名、意味が名前で示されていない数値、重複した計算と表示があります。このコードを読み、**料金・オブジェクトの状態・表示内容を保ちながら、構造を改善してください。**

今回は、一つのプログラムを3段階で改善します。配布コードはリファクタリングするための変更前のプログラムです。完成例ではありません。空のメソッドを一から埋める課題とは異なり、動作を確認してから、少しずつ書き換えます。

## 配布ファイル

| ファイル | 役割 | 今回の扱い |
| --- | --- | --- |
| book.py | 本のタイトルと1日あたりの延滞料金 | そのまま利用する |
| loan.py | 利用者、本、延滞日数を持ち、料金を計算する | 計算の構造を改善する |
| main.py | 本と貸出を作り、3件の明細を表示する | 重複した表示を整理する |
| test_loan.py | 料金と状態を確認する12個のテスト | 完成済みの確認用テストとして使う |
| expected_output.txt | 変更前の正しい表示、18行 | 変更後の表示と比較する |
| REPORT.md | 読み取った内容と変更の記録 | 自分の説明とコードを記入する |
| requirements.txt | 必要なパッケージ | 環境の準備に使う |

`display.py`は最初にはありません。第3段階で自分で作成します。フォルダーを段階ごとにコピーする必要はありません。同じファイルを順番に改善してください。

## 本と貸出の関係

### Book

| 属性 | 型 | 意味 |
| --- | --- | --- |
| title | str | 本のタイトル |
| daily_late_fee | int | 延滞1日あたりの料金、円 |

### Loan

| 属性 | 型 | 意味 |
| --- | --- | --- |
| borrower | str | 利用者の名前 |
| book | Book | 料金計算に利用する本のオブジェクト |
| overdue_days | int | 延滞日数 |
| is_student | bool | 学生ならTrue。省略時はFalse |

`Loan`の`book`には、本のタイトルだけでなく、`Book`のインスタンスが入っています。`get_fee()`は、その本の`daily_late_fee`を参照して料金を返します。

同じ`Book`を複数の`Loan`から参照できます。`main.py`ではAkiraとMariaの貸出が同じ`book1`を使っています。片方の料金計算で本の1日料金を書き換えると、もう片方にも影響します。**計算時はLoanとBookの属性を変更しないでください。** この教材では貸出料金の記録だけを扱い、本の在庫や同時貸出の制限は扱いません。

## 料金のルール

1. 延滞日数が0なら料金は0円です。
2. 本の1日料金と延滞日数から基本料金を求めます。
3. 基本料金が1000円を超えた場合は、1000円に制限します。
4. 学生の場合は、**上限を適用した後の料金**から50%を割り引きます。
5. 1円未満は切り捨て、結果を整数で返します。

**上限と割引の順序を変えないでください。** 1日100円、延滞15日の学生は、1500円を1000円に制限してから半額にするため500円です。先に割引すると750円になり、元のルールと違います。

| 1日料金 | 延滞日数 | 学生 | 上限適用後 | 最終料金 |
| --- | --- | --- | --- | --- |
| 100円 | 0日 | いいえ | 0円 | 0円 |
| 100円 | 3日 | いいえ | 300円 | 300円 |
| 100円 | 3日 | はい | 300円 | 150円 |
| 100円 | 10日 | いいえ | 1000円 | 1000円 |
| 100円 | 15日 | はい | 1000円 | 500円 |
| 151円 | 1日 | はい | 151円 | 75円 |

入力データは正しいものとします。1日料金は正の整数、延滞日数は0以上の整数、名前とタイトルは空でない文字列、学生区分はboolです。この課題では入力画面、例外処理、データ保存、新しい割引制度は追加しません。

6. `REPORT.md`の「元のコードの読み取り」を記入します。

ここまではコードを変更しません。最初からテストが成功するのは、元のプログラムが料金のルールを満たしているためです。**テストが成功しただけでは、この課題は完成ではありません。**

## 第2段階：料金計算を整理する

`loan.py`を、小さな変更に分けて改善してください。各変更の後にテストを実行します。

### 1. 名前と定数

- ローカル変数`x`を、役割が分かる名前に変更します。
- 上限の1000を`MAX_LATE_FEE`、学生割引率の50を`STUDENT_DISCOUNT_PERCENT`というモジュールの定数にします。
- 同じ意味の数値には同じ定数を使います。百分率を表す計算の100まで、無理に定数へ置き換える必要はありません。

### 2. 計算の役割を分ける

`Loan`に`get_capped_fee(self) -> int`を追加します。

| メソッド | 役割 |
| --- | --- |
| get_capped_fee() | 延滞がなければ0。延滞があれば基本料金に上限を適用した金額を返す。学生割引は扱わない |
| get_fee() | get_capped_fee()の結果を利用し、必要なら学生割引を適用した最終料金を返す |

- 学生かどうかに関係なく使う、基本料金と上限の計算を重複させないでください。
- 結果が決まる場合は早期リターンを使い、深い条件の入れ子を整理してください。
- `get_fee()`の名前と呼び出し方は変えません。既存のテストとシナリオから、引き続き呼べるようにします。
- `get_capped_fee()`も`get_fee()`も、属性の変更や画面への表示を行いません。
- 引数と戻り値の型ヒントを付けます。`self`自身の型は不要です。

Mariaの例では、`get_capped_fee()`が1000、`get_fee()`が500を返します。元の12個のテストは外部から使う`get_fee()`を確認します。新しいメソッドへの分割や重複の削除は、コードを読んでも確認してください。

## 第3段階：表示を共通化し、ファイルを分ける

`main.py`では、同じ形式の表示が3回書かれています。

1. まず`main.py`内で、1件分の表示を`print_loan(loan: Loan) -> None`という関数にまとめます。
2. 3件の貸出を、それぞれ同じ関数へ渡します。関数内では受け取った`loan`を使い、新しい本や貸出を作りません。
3. この時点で`main.py`を実行し、元の18行と同じ表示になることを確認します。
4. `display.py`を作り、確認した関数をそのまま移します。必要なインポートを追加し、`main.py`から関数をインポートします。
5. `main.py`に古い関数定義や重複する表示を残さないでください。
6. 再度、全テストと表示を確認します。

`print_loan()`は6行の明細を表示する関数です。計算を複製せず、最終料金は`Loan`のメソッドから受け取ります。戻り値をさらに`print()`すると余分な`None`が表示されるので、関数を直接呼び出してください。

最終的な役割は次のとおりです。

| ファイル | 役割 |
| --- | --- |
| book.py | 本のデータ |
| loan.py | 貸出のデータと料金計算 |
| display.py | 1件の貸出明細の表示 |
| main.py | サンプルの作成と実行順序 |
| test_loan.py | 計算結果とオブジェクトの状態の確認 |

## 変更してはいけないもの

- BookとLoanのクラス名、既存の属性名、インスタンスの作成方法。
- `get_fee()`の名前、引数、戻り値の意味。
- 上限、割引率、適用順序、端数の切り捨て。
- 計算前後のLoanとBookの属性値、および同じBookを共有する関係。
- `main.py`にある3件のデータと表示順序。
- `expected_output.txt`の内容、および正しいテストの期待値。

`book.py`、`test_loan.py`、`expected_output.txt`はそのまま利用します。今回はテストを作る練習ではなく、同じテストを使ってコードの改善を確かめる練習です。
